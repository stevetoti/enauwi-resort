# E'Nauwi Beach Resort - SEO Review

1 November 2026 | https://www.enauwibeachresort.org/

## What matters most

The website has a sound technical foundation, but its booking and services pages give search engines very little useful content in the initial response. Improve those pages first, then align accommodation, restaurant and conference copy with clear search intents. Correct a wrong-island image description and verify operational claims before promoting them further.

**Coverage:** all 37 sitemap URLs checked; 22 published blog articles and 8 activity detail pages. No website changes published. 126 keyword candidates and draft metadata for all 37 URLs are prepared for review.

## Confirmed strengths

- All 37 sitemap URLs returned successfully. Public pages have canonical URLs; host variants converge to the preferred HTTPS website.
- A deliberately missing page returns a genuine 404.
- The home page already contains business and website structured data.
- The analytics tag is present and the public search-verification file returns successfully.
- Public search returns the official website and several articles. Exact country-specific Google positions were not measured.

## Priority findings

|---|---|---|---|
| High | /book: 9 visible words and no heading in initial HTML | Accommodation content depends on JavaScript | Render useful bungalow copy and a heading before interactive loading |
| High | /services: 8 visible words and no heading in initial HTML | Conference and service content depends on a browser data request | Render a useful introduction, heading and confirmed service information |
| High | Keyword and ranking account rejects authentication | Demand and exact position cannot be measured | Restore access, then validate the candidate map |
| High | Conference operating status differs between website and tourism listing | Guests may receive conflicting information | Owner confirms opening, capacity and current facilities |
| Medium | Homepage image describes Malekula instead of Efate | Conflicting location signal and inaccurate accessibility text | Correct to Efate Island, Vanuatu |
| Medium | /menu initial HTML contains only 23 visible words | Dining page has limited useful crawlable information | Add restaurant details and current-menu context |
| Medium | 13 pages have no page-specific structured data | Navigation and content types can be clearer | Add useful inner-page and service markup where supported |
| Medium | Several travel articles overlap in topic | Pages may compete for similar queries | Inspect actual search queries before merging or retargeting |
| Low | 20 titles over 60 characters; 8 descriptions over 160 | Search snippets may be truncated | Use the prepared concise, distinct metadata drafts |
| Low | Activity gallery thumbnail buttons lack explicit labels | Assistive technology may not identify image selectors | Add descriptive button names |

The initial-HTML findings were checked against both fetched pages and source behavior. They show a JavaScript dependency, not proof that Google cannot render or index the pages. A rendered-browser comparison is still required before release. The automated homepage business-schema warning is a false positive: the existing resort markup is present. Empty thumbnail alt text can be appropriate when the control itself is labelled.

## Prepared changes and release boundary

The review package includes exact search titles and descriptions for all 37 existing pages, revised headings and introductions for six core pages, 16 FAQ answers across four pages, a keyword-to-page map, a local-profile copy draft and 12 future content briefs. All are drafts. No live settings, source pages, article records, profiles or scheduled jobs were modified.

Recommended first release: render booking/services content, apply reviewed metadata, correct geography, add useful internal links and FAQ copy, add relevant structured data, and label gallery controls. Preserve existing URLs and booking flows. A wedding page is a later opportunity once facts and demand are confirmed.

Before release, verify types, lint, production build, browser interactions, one main heading per page, canonical URLs, structured data, public verification file and mobile layouts. Then deploy a committed, pushed revision and repeat the crawl. No improved score is claimed before that check.

## Access and decisions needed

- Restore keyword research authentication. Never send account passwords in chat.
- Review search indexing and performance in the search-owner account, and validate analytics booking/enquiry events.
- Confirm the business map pin, current address, phone, email, opening hours and profile access.
- Confirm conference availability, transfer terms, breakfast inclusions, and activity operators/locations. Wildlife sightings must never be promised.
- Approve the concrete first-release fix plan before site changes are applied.

## Recommended sequence

1. Approve the first-release fixes and confirm operational facts.
2. Implement and verify the core-page improvements; publish through the normal release process.
3. Restore measurement access and validate demand, queries, conversions and local-profile details.
4. Refresh the strongest existing articles and commission differentiated guides. Review progress after indexing; timing varies and no position is guaranteed.
